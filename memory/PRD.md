# NetOps CRM (Wispro-style ISP CRM) — PRD

## Original Problem Statement (resumen)
CRM para negocio ISP tipo Wispro: dashboard, clientes con fecha de pago flexible, pagos (efectivo/transferencia/promesas/facturas manuales), WhatsApp secundario para recordatorios y bandeja, configuración del negocio, usuarios de sistema por rol (dueño, técnico, secretaria, admin), OLT/ONUs (potencias, IP, umbrales), Mikrotik (vía VPN o IP pública), planes, leads (instalación/lentitud/cambio contraseña/domicilio), servicios extras (IPTV, telefonía, megas, energía), mapa NAP con capacidad, desconectados > 30 min con acción WhatsApp, tareas/embudos.

## User personas
- **Dueño (owner)**: acceso total, configura negocio, crea usuarios, ve reportes.
- **Admin**: gestiona clientes/planes/pagos y usuarios operativos.
- **Técnico**: campo y red — leads, ONUs, mapa, WhatsApp.
- **Secretaria**: cobranza, pagos, WhatsApp.

## User Choices (Feb 2026)
- Auth: JWT propio (email + password, bcrypt, cookie httpOnly + Bearer).
- WhatsApp: **simulado** (guardado en DB; enviar luego con proveedor real).
- OLT / Mikrotik: **mockeado** con estructura lista para vincular por VPN / IP pública.
- Pagos: registro manual (efectivo/transferencia/promesas). Stripe **diferido**.
- Alcance MVP acotado.

## Arquitectura
- Backend: FastAPI + Motor (Mongo) + PyJWT + bcrypt. Todas las rutas bajo `/api`.
- Frontend: React 19 + Tailwind + Shadcn + Recharts + react-leaflet + sonner.
- Auth: cookie httpOnly `access_token` + fallback Bearer; RBAC vía `require_roles`.
- Mongo con `id` UUID string (sin ObjectId leak).

- **Smart Life · Tuya IoT (2026-02-14)**: nuevo módulo `/smart-life` (sidebar Operación, ícono AirVent) para controlar A/Cs y dispositivos IoT vinculados a Tuya Cloud. Backend: `tuya.py` con cliente async completo — firma **HMAC-SHA256** oficial (stringToSign = method + Content-SHA256 + headers + url; sign_str = client_id + [token] + t + nonce + stringToSign), auto-refresh de token cuando faltan <60s, retry automático en 1010/1011 (token expirado), soporte multi-región (US/EU/CN/IN + subregiones US-west/east). Endpoints: `GET/PATCH /api/tuya/config` (credenciales guardadas en `tuya_config` singleton, secret enmascarado en respuestas), `POST /api/tuya/test-auth` (fuerza refresh para validar creds), `GET /api/tuya/devices` (lista v1.3/iot-03 con fallback a v1.0/iot-01, incluye estado en línea + status DPs), `GET /api/tuya/devices/{id}/status`, `POST /api/tuya/devices/{id}/commands` (envía código+valor: switch, temp_set, mode, fan_speed_enum), `PATCH /api/tuya/devices/{id}` (renombrar), `DELETE /api/tuya/devices/{id}` (quitar del proyecto). Errores Tuya se propagan como HTTP 424 con `Tuya {code}: {msg}`. Frontend `SmartLife.jsx`: tarjeta de configuración con toggle mostrar/ocultar, campos Access ID + Secret (enmascarado si está guardado) + Region select + Project Code, botones "Guardar credenciales" y "Probar conexión" con feedback tricolor; 3 KPIs (Total/Online/Encendidos); grid responsive de DeviceCards que muestran estado ON/OFF, temp actual, modo (frío/calor/deshu./ventilar/auto con iconos + color), switch ON/OFF, slider de temperatura 16-30°C con botones ±, Select para modo + velocidad de ventilador, botón Renombrar (Dialog con input) y Eliminar (confirm nativo). Verificado en vivo: fake creds guardadas → botón test-auth hace request real a openapi.tuyaus.com y devuelve `Tuya 2009: clientId is invalid` correctamente (confirma que la firma HMAC-SHA256 está bien construida).
